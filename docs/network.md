# Network statement

Exactly what the tracker sends off your machine, and when. Written from a read of the source after the app moved onto the project catalogs (D49); each row names the code so it can be checked. The companion document is [threat-model.md](threat-model.md).

The short version: **nothing leaves the machine unless you use one of the three features below, and each is yours to turn on.** There is no telemetry, no analytics, no update check and no account.

## What stays local

Scanning and importing, metadata extraction (ExifTool), reading credentials (the C2PA library, against the pinned trust lists on disk), classification, timeline import and matching, building the manifest, signing itself, and building the public export all run on your machine. The app's pages load no fonts, scripts or images from other sites.

A timeline file names where its sources were on the editor's machine. The tracker opens such a path only inside the project's media folders, and never one on another computer (D65), so importing a timeline connects to nothing.

Where a signed copy is published (the web address of the signed file and of its page, D56) is only recorded. The tracker never fetches either address, not to check it and not to preview it.

## Not measured yet

Stated so nobody has to take the table above on trust further than it has been checked.

- **Your identity (D55)** adds nothing that leaves the machine: the identity assertion is signed here, with your identity key, and has no time stamp of its own.
- **A correction (24 Nov 2026):** some files keep their Content Credentials on the web and carry only an address for them; Adobe Firefly's videos point to `cai-manifests.adobe.com`. Until D51, `c2patool` fetched such a manifest whenever it read the file, at `extract` and, for ingredients, while signing, and this statement did not say so. The request names the manifest, which identifies the file, and comes from your machine's address. It was found by checking the bytes of a Firefly video that `c2patool` had read in full: it contains no manifest, only the address.
- A C2PA reader may also check a certificate's revocation online (OCSP), and could fetch a trust list given to it as an address. The C2PA library that now reads files does neither: OCSP is off, the trust lists are given to it as text, and it is handed a fetch function that refuses every request it would make for a trust list (`packages/core-node/src/extract/c2pa-library.ts`, D51). Nor does it fetch credentials stored on the web any longer: that fetching is off, and the tracker makes that request itself when you have allowed it (D74, the table above). That is from its settings and code, and from a test that reads such a file with no network; not yet from watching the network.
- This statement comes from reading the code, not from a packet capture.

## The public viewer is a separate thing

`public-viewer/` is a web page you host for your audience. It is not part of the local tool and sends nothing from your machine. A visitor's browser, on that page, loads fonts from Google Fonts, loads YouTube's player script and plays through `youtube-nocookie.com` if you embed a YouTube video, and offers a link to `contentcredentials.org/verify`. When the page passes no download link of its own, the viewer links the signed file at the https address the export records (format 2, D57), and the page's own address if the export names one; nothing is fetched from those addresses until the visitor follows a link. Checking a copy the visitor already has (D58) reads that file on their device and sends nothing anywhere. A page that also reads the copy's Content Credentials (D61) has the visitor's browser load the C2PA reader the page built, including a 9 MB WebAssembly file, and the trust list, from wherever the page hosts them; the copy itself still stays on the device. See `public-viewer/README.md`.

## Development

`npm install` downloads packages from the npm registry, and `npm run audit` asks the same registry which of the installed versions have known advisories, sending the list of package names and versions. No package's install script runs (`.npmrc`), so the C2PA library's does not download its native binary unchecked (D69). `npm run tools:fetch` downloads each pinned helper program and the C2PA library's native binary from `github.com` release pages, and the C2PA trust lists from `raw.githubusercontent.com` at a pinned commit, and checks each against a recorded SHA-256; it sends nothing but the request for that file. Tests use no network. CI and Renovate run on GitHub, not on your machine.
